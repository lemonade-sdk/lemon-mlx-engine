**Date:** 2026-08-08  
**Branch:** `exp/redline-kernel-launch` @ `b836aaa`  
**Host:** gfx1150 · model `Qwen3.5-0.8B-4bit` local snapshot  
**Protocol:** `./build/chat`, `--max-tokens 64 --temperature 0 --raw`, fixed prompt; parse last `Generation:` line from stderr.

---

## What “Redline ON” means **today** (plain language)

| Mode | Env | What actually runs |
|------|-----|--------------------|
| **Eager (baseline)** | unset | Product decode only (`call_fn` / HIP) |
| **Session only** | `MLX_REDLINE_DECODE=1` | One-shot dlopen + `gpu_new` + gd_bind log; **model still product** |
| **Sidecar ON** | `DECODE=1` + `HSACO=…` + `SIDECAR=1` | Toy retained-PM4 **extra** work each L=1 token **beside** product forward — **does not replace** matmul/qmm |

So “turn it on” does **not** mean “the model now runs on Redline.”  
It means “Redline session (+ optional toy sidecar) is active **while** the model still uses the normal path.”

**“Product path ownership”** (earlier jargon) = Redline would have to **replace** some real decode kernels (or encoder launches) that currently cost time. Until then, gen t/s is expected to be **≈ same**, or slightly **worse** if the sidecar adds work.

**Sidecar correctness** (same run): `fullgen PASS n=64 side_obs=2080 side_exp=2080` — toy accumulator math OK; **not** a model-speed claim.

---

## Interpretation

1. All four gen rates sit in a **~115–117 t/s** band — noise is ~2 t/s between baseline repeats alone.  
2. Redline ON (session or sidecar) is **not a clear win** and **not a clear lose** on this short 64-token sample.  
3. That matches the architecture: **product matmul still dominates**; Redline is not carrying the forward.  
4. Launch-floor wins (E1/E2/P2) remain real for **multi-dispatch microbenches**, not yet transferred into model gen t/s.

## How to turn ON yourself

```bash
export PATH=/opt/rocm/core/bin:$PATH
export LD_LIBRARY_PATH=/opt/rocm/core/lib:/tmp/redline-warpfront-target/release:$LD_LIBRARY_PATH
export MLX_REDLINE_DECODE=1
export MLX_REDLINE_LIB=/tmp/redline-warpfront-target/release/libredline_dispatch.so
# full stack (session + micro + L1 sidecar):
export MLX_REDLINE_HSACO=$PWD/docs/experiments/redline-kernel-launch/logs/acc_kernel-gfx1150.co
export MLX_REDLINE_SIDECAR=1
./build/chat <model> --max-tokens 64 --temperature 0 --raw
```

Default product path: leave all `MLX_REDLINE_*` **unset**.

---

## What would make “ON” actually faster

Need a **product-owned** Redline path: replace a **real** launch-heavy piece of the decode DAG (not the toy `acc_k` sidecar), then re-run this A/B. Until then, gen t/s A/B is a **health check**, not an optimization result.
